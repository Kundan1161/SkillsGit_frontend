# Sentry Commit Message Conventions

## When to use

Use this skill when authoring git commits in Sentry-style projects — formatting subject lines, writing bodies that explain *what and why*, and referencing issues correctly.

## How to apply

Always check current branch first with `git branch --show-current`. If on `main` or `master`, create a feature branch first (without asking) and re-verify before committing. Then format the commit as `<type>(<scope>): <subject>` with optional body and footer, all lines under 100 characters.

## Core Structure

```
<type>(<scope>): <subject>

<body>

<footer>
```

All lines under 100 characters.

## Before Committing

Always check your current branch:

```bash
git branch --show-current
```

If on `main` or `master`, create a feature branch first — do not ask the user; just proceed and re-verify before committing.

## Commit Types

12 types: `feat`, `fix`, `ref`, `perf`, `docs`, `test`, `build`, `ci`, `chore`, `style`, `meta`, `license`.

## Subject Line Standards

- Imperative present tense ("Add feature", not "Added feature").
- Capitalize the first letter.
- No trailing period.
- ≤ 70 characters.

## Body Requirements

- Explain **what** and **why**, not how.
- Imperative mood.
- **Never include customer data** (names, emails, PII) — reference internal tickets instead (`Fixes SENTRY-1234`).

## Issue References

- `Fixes GH-1234` — closes a GitHub issue.
- `Fixes #1234` — same, short form.
- `Fixes SENTRY-1234` — closes a Sentry/Jira issue.
- `Refs ...` — links without closing.

## AI Attribution

Include `Co-Authored-By:` in the footer when an agent generates changes, using the agent's identity. Do not add phrases like "Generated by AI" elsewhere in the message.

## Example

```
feat(api): Add streaming response support for /v1/chat

Streaming improves perceived latency for chat clients by emitting tokens as
soon as the model produces them. Adds a new SSE endpoint and updates the
docs example.

Fixes SENTRY-4821
Co-Authored-By: Claude <noreply@anthropic.com>
```
