# PBR Material Authoring Methodology

## When to use

Use this skill when authoring physically based materials that have to read correctly across multiple lighting conditions, render engines, or viewing displays — not just look acceptable in the one lookdev light rig the artist happens to have open. It is the right skill for a lookdev artist setting up a hero asset's texture sets, for a texture artist asked to "make this match real life," for a technical director writing the studio's material authoring standard, and for anyone debugging a material that looks correct in one shot and wrong in another.

Skip it for stylized non-physical materials where the goal is illustrative rather than measured, for one-off marketing renders where look-by-eye is faster than calibration, or for early concept work where the lookdev is still being explored. Reach for it the moment a material has to survive lighting changes, the moment a measured reference is available, or the moment more than one artist will touch the same material library.

## How to apply

1. Decide on the **shading model** before any maps are authored. Modern production has converged on a single über-shader expressing diffuse, specular, transmission, subsurface, sheen, and coat lobes with energy conservation between them. The choice of shading model dictates which maps are meaningful, which combinations are physically valid, and how parameters compose. Pick one shading model for the project and lock it; do not author half the assets in one model and half in another.
2. Choose between the **metallic-roughness workflow** and the **specular-glossiness workflow**. Metallic-roughness is the dominant convention: a base color map plus a binary-ish metalness map plus a roughness map, with the shader deriving dielectric F0 from a fixed index of refraction and metal F0 from the base color. Specular-glossiness exposes the specular color directly and is more flexible for legacy assets and a few edge cases. Pick metallic-roughness unless a specific reason forces specular-glossiness; mixing them within one project is a recipe for inconsistency.
3. Plan the **texture-set partitioning**. A texture set is a group of maps that share UV space, resolution, and material assignment. The default rule: one texture set per material region with materially different shading needs (metal hardware on a wooden prop is one set; the wood is another). For UDIM workflows, a single texture set covers many tiles; for non-UDIM workflows, each object or material id becomes its own set. Document the partition before painting; re-partitioning halfway through is expensive.
4. Allocate **UDIM tiles** with intent. UDIMs let a single texture set address many UV regions — useful for characters with dense face detail, props with many components, and environments with high resolution requirements. Reserve specific tile ranges per region (the convention "1001 through 1009 for the body, 1011 through 1019 for the head, 1021 for the props" keeps human readers oriented). Aim for similar resolutions within a tile range; mixed-resolution UDIMs are valid but harder to budget. Do not let UDIMs spill across the 10-tile row boundary; the system supports it but human readers and some tools get confused.
5. Pick a **per-tile resolution budget**. A general rule: hero close-up tiles deserve 4K or 8K, mid-distance tiles 2K, background tiles 1K, set-dressing 512 or 1K. Budget total memory: each 4K, 16-bit float, 4-channel UDIM tile costs roughly 128 MiB; multiply by tile count and map count to size the project's texture memory budget. If the budget exceeds available VRAM by a wide margin, plan for texture streaming or reduce hero resolution before authoring begins.
6. Establish **color-space discipline** by map type. Base color is authored and stored in a perceptually encoded color space (the convention is sRGB encoding for albedo maps or a wide-gamut equivalent), and the shader linearizes on read. Roughness, metalness, normal, ambient occlusion, displacement, and any scalar map are linear (raw) data and must be stored and read without gamma transformation. Mixing this up — storing roughness as sRGB-encoded, for instance — produces the very common "the material looks too shiny" failure. Mark each map's color space in the sidecar metadata; the lookdev step reads it and configures the texture lookup accordingly.
7. Author **base color** within physically plausible value ranges. No dielectric material has a base color brighter than the canonical white-paint value (around 0.85 linear); no dielectric is darker than the canonical fresh-asphalt value (around 0.02 linear). Pure metals do not have a meaningful base color in the dielectric sense; their base color encodes the metallic F0 (gold around 1.0/0.71/0.29; aluminum around 0.91/0.92/0.92; iron around 0.56/0.57/0.58). Clip any painted base color that strays into impossibly bright or dark territory.
8. Treat **metalness as a binary** with intentional intermediate values. Almost every real material is either metal or not metal; intermediate values exist only at the pixel-blend boundary between the two on a multi-material surface. Painting a "0.5 metal" mid-tone uniformly across a region is almost always a mistake; what looks like a semi-metallic material is usually a dielectric with high specular and a low roughness. Reserve intermediate metalness for transitions on dirty, worn, or layered surfaces where the underlying mask is genuinely mixed.
9. Author **roughness** as the principal control of material identity. Roughness drives the apparent surface micro-detail and is what artists most often need to tune. Useful anchor values: polished mirror surfaces 0.02 to 0.05; smooth gloss paint 0.1 to 0.2; satin or eggshell 0.3 to 0.4; matte rubber and unfinished wood 0.6 to 0.8; chalk and fresh stone 0.85 to 0.95. Avoid pure zero and pure one — pure zero produces aliasing on highlights, pure one removes specular response entirely and looks unnaturally dead. Roughness almost never wants to be a flat value; even apparently uniform materials benefit from a low-amplitude noise overlay to break up specular highlights.
10. Author **normal maps** in tangent space with a documented convention. Tangent-space normal maps are the production default: they survive deformation, are reusable across UVs, and store compactly. Decide and document the green-channel convention (Y-up versus Y-down; OpenGL-style versus DirectX-style) and lock it for the project. A mismatch shows up as inverted concavity — bumps look like dents and vice versa. Keep normal-map blue channel above 0.5 in the painted region (positive Z); below-0.5 blue is non-physical and tells the eye something is wrong.
11. Use **displacement** for silhouette-affecting detail and **normal maps** for shading-only detail. Displacement is expensive at render time and requires subdivision; reserve it for cracks, dents, large bumps, and any feature that should change the contour of the model against the background. Normal maps handle the rest. Bake displacement and normal from a high-resolution sculpt at the same scale, in the same tangent space, against the same low-poly UV layout; mismatches create the "the silhouette is fine but the lighting looks wrong" failure.
12. Author **ambient occlusion** as a low-frequency contact map, not as a shading shortcut. AO captures contact darkening at crevices and corners that a global-illumination renderer may under-resolve at typical sample counts. Use it gently and multiply with diffuse only; over-applied AO produces a dirty, painted-shadow look that breaks under lighting changes. In a path-traced renderer with enough samples, AO contribution should be small enough that disabling it does not change the look dramatically — if disabling it changes the look dramatically, the AO is doing the renderer's job badly.
13. Plan **procedural-versus-scanned authoring** explicitly. Procedural materials (built from noise, tilings, and graph-based operators) are resolution-independent, easy to vary, and easy to share across assets; scanned materials (photogrammetry, surface scans) carry real-world fidelity, irregularity, and authored history that is hard to fake procedurally. Hero assets typically benefit from scanned-as-base with procedural detail layered for variation; background assets are typically all-procedural for memory and authoring time. Document which approach applies per material and why.
14. Calibrate against **measured reference**. A measured-reference dataset (a captured BRDF, a calibrated photograph of the real material under a known light, or a reference value from a measured material library) is the only way to confirm that an authored material is correct rather than merely plausible. Build a neutral test scene with a calibrated light and a calibrated background, render the authored material side by side with the reference, and compare values via a known sampling point. Calibrate the brightest highlight, the deepest shadow, and a mid-tone region; if all three match, the material is within tolerance.
15. Run a **lookdev test rig** against every hero material. A lookdev rig includes: a calibrated HDRI environment for image-based lighting; a controlled three-point light arrangement; a turntable that exposes the material to back, side, and head-on lighting in sequence; a neutral gray and chrome ball in frame for white-balance reference; a macbeth-style color chart for color-balance reference. Render the rig once per material. Inconsistencies between hero and turn lookdev usually trace to one of these elements drifting.
16. Plan **energy conservation** as a hard rule. Specular reflection plus diffuse transmission plus subsurface contribution must not exceed incident energy. Modern shading models enforce this when used through their canonical parameter set; trouble starts when textures push parameters into combinations the model cannot enforce (high coat plus high specular plus full base color, for instance). If a material brightens visibly when lit from many directions at once, that material is over-energetic and must be re-balanced.
17. Document **handoff to lookdev**. The texture publish is a directory of UDIM-numbered files with a sidecar JSON describing each map's role, color space, value range, and intended shader input. Lookdev consumes the publish, binds the maps to the shading model, and authors the material binding layer that the asset assembly composes in. The texture authoring step does not own the binding; the lookdev step does.
18. Build a **QC checklist** that runs before any texture publish. Required checks: every UDIM tile present (no gaps within the declared range); roughness within 0.02 to 0.98; base color within plausible value ranges; metalness binary except where intentionally transitional; normal-map blue channel positive in painted regions; AO multiplied by diffuse-only, not by specular; no tile resolution exceeds the project budget; no painted seam crosses a UV island boundary. Run the checklist as an automated tool whenever possible; do not rely on the artist remembering it.

- A color-space matrix assigning the correct space to each map type.
- A calibration procedure for validating against measured reference.
- A pre-publish quality-control checklist.

## Examples

**Hero character with three texture sets, scanned-base hybrid authoring.** Sets: head (UDIMs 1001 to 1004 at 4K), body (UDIMs 1011 to 1018 at 4K), props (UDIM 1021 at 2K). Maps per set: base color (sRGB-encoded), metalness (raw), roughness (raw), normal (raw), AO (raw), thickness for subsurface (raw). Scanned base on the head from a calibrated capture; procedural detail layered for pores and freckles. Body uses scanned fabric weaves with procedural wear; props are all-procedural metal hardware. Calibration: a measured skin-tone reference renders side by side with the authored material on the lookdev rig; mid-tone and highlight match within a tolerance. QC: every declared UDIM present, roughness within bounds, no out-of-bounds base color.

**Architectural archviz interior, UDIM-tiled environment with measured material library.** One texture set per material id (floor, wall paint, wood trim, brushed metal, painted ceiling). Resolutions sized to camera distance: 8K for the floor and dominant wall, 4K for trim, 2K for ceiling. Color space: base color sRGB-encoded, all scalar maps raw. Roughness calibrated against a measured value per material (matte interior paint at 0.7, eggshell at 0.4, brushed metal at 0.25 with anisotropic detail in the normal). Procedural authoring throughout, with photographs used as reference rather than as scanned source. AO baked from the model and multiplied gently on diffuse only.

**Background prop, all-procedural, single texture set.** One 2K UDIM tile. Authoring method: graph-based procedural built from one noise pattern, one curvature mask, and one base color palette. No scanned input. Roughness varies by curvature so worn edges read differently from flat regions. Metalness binary by material region. Normal map baked from a low-detail sculpt to add silhouette breakup. AO multiplied gently on diffuse. Calibration is light: the material is checked against the project's reference props for tonal consistency rather than against a measured BRDF.

## Limitations

- This skill assumes a physically based shading model with energy conservation. Stylized non-physical workflows have different rules and this skill does not address them.
- Measured-reference data for some materials (translucent stones, iridescent surfaces, biological tissue) is hard to obtain; the calibration step degrades to "plausible against photographs" in those cases.
- Renderer-specific shading-model implementations differ in parameter mapping, anisotropy handling, and energy-conservation policy. Materials calibrated against one renderer's reference may need re-balancing against another's.
- This skill does not enumerate the per-engine UV import quirks, anisotropy direction conventions, or texture-streaming requirements; verify against the chosen renderer's documentation before locking the authoring standard.
