## When to use

Invoke this skill when an agent is asked to set up, audit, or troubleshoot colour management across a photography workflow and the question concerns more than a single image. Common triggers:

- A photographer is bringing a new editor or display online and needs to choose working colour space, set up monitor calibration, and decide which profiles to embed on export.
- Prints from a lab look different from on-screen previews and the agent needs to diagnose where colour drift entered the pipeline.
- Files from two photographers shooting the same job look subtly different and the team wants a colour-management protocol they can both follow.
- A move from screen-only delivery to mixed screen-and-print delivery requires soft-proofing to be added to the workflow.

Do not invoke this skill for retouching technique (use the retouching skill), for RAW developer step ordering (use the development-pipeline skill), or for asset-management strategy (use the asset-management skill). Defer to a print-shop's own documentation when a specific commercial printer publishes calibration targets that override generic guidance.

This skill assumes ICC-based colour management, the long-standing industry standard. If the user's environment uses a different model (display calibration via OS-level only without ICC profile generation, for example), the skill should still apply the principles but note the limitation.

## How to apply

Walk the colour pipeline from capture to delivery. At each stage, decide which colour space is in use, which profile describes the device or file, and which transform translates between adjacent stages.

### Stage 1: Capture and camera profile

1. Distinguish between the camera's raw sensor data, which has no colour space, and the embedded preview JPEG, which does. RAW developers interpret the sensor data into a colour-managed working space using a camera profile (often a DCP or DNG profile). The user's choice of camera profile in the RAW developer is one of the most under-appreciated colour decisions in the pipeline.

2. For accurate-colour work (product photography, fine-art reproduction, dermatology) prefer a custom camera profile built from a colour reference target shot under the same lighting as the production frames. Generic camera-vendor profiles trade accuracy for pleasing rendering and are not suitable for measurement-grade work.

3. For interpretive work (portrait, editorial, landscape) the camera-vendor's matrix profile or the RAW developer's matching "standard" profile is usually a fine starting point. Switch to a different camera profile only with intent — the choice changes hue rendering across the whole image and is easy to second-guess if the user does not know it changed.

4. White balance and camera profile interact. A white-balance change after switching camera profile may produce a different colour than the same white-balance change before. Decide camera profile first, then white balance, then everything else.

### Stage 2: Working space

5. Pick the RAW developer's working space by the colour range the source captures, the destination delivers, and the editor's bit depth.

   - sRGB working space: a smaller gamut than most modern cameras capture. Suitable only when the entire downstream pipeline is sRGB and there is no possibility of upgrading later. Clipping in saturated reds and yellows is common with sRGB working space.
   - Adobe RGB working space: a moderate gamut covering most reflective print processes. A reasonable default for mixed web and print delivery on 8-bit and 16-bit files.
   - Display P3 working space: closer to modern wide-gamut displays. Suitable for delivery to known wide-gamut devices.
   - ProPhoto RGB working space: a very large gamut that exceeds most output devices. Use only at 16-bit; at 8-bit it produces banding because the bins are too coarse. ProPhoto is recommended for archival masters and for retouchers handing files back and forth, not for end delivery.

6. Match bit depth to working space. The wider the gamut, the more bits per channel are needed to avoid banding. 16-bit for Adobe RGB and wider; 8-bit acceptable only for sRGB and small-gamut delivery.

7. Never change working space inadvertently. Editors that "assign" a profile when they should "convert" can shift colour without warning. Convert is the correct operation when the visual appearance should be preserved across spaces; assign is correct only when an unprofiled file's contents are known to be in a particular space and need to be tagged.

### Stage 3: Display calibration and characterisation

8. Calibration and characterisation are not the same. Calibration adjusts the display's hardware (or its graphics-card lookup table) to hit a target white point, gamma, and luminance. Characterisation measures what the display does after calibration and writes a profile describing it. Both steps are needed.

9. Recommended calibration targets for photo work:

   - White point: D65 (6500 K) for most work. Some print houses target D50 to match print viewing booths; align with the lab if proofing to a specific booth.
   - Luminance: 80 to 120 cd/m² for print proofing in a controlled-light room. 120 to 160 cd/m² for screen-only delivery in normal office light. Above 160 cd/m² shadows look opened relative to a print viewed under the same light.
   - Gamma: 2.2 is standard for most photo workflows. L* and sRGB tone-response curves exist but offer no benefit for typical photographic delivery.

10. Cadence: recalibrate at least monthly for production work, more frequently for high-stakes print proofing, immediately after any change in the room's ambient light (new window blinds, new bulbs, daylight-saving shift in winter light). Modern displays drift slowly but they do drift, and a months-old profile may be wrong without the user noticing.

11. Use a hardware colorimeter or spectrophotometer; software-only "visual" calibration is not adequate for any work delivered for money. Verify the instrument itself is in date — colorimeter filters age over a multi-year scale.

12. The room matters as much as the display. Work under stable, neutral, moderate ambient light. A bright window behind the display contaminates every colour decision. Paint the wall behind the display a neutral mid-grey if possible; many surveyed practitioners cite the room as the single biggest unattributed source of colour disagreement between collaborators.

### Stage 4: Editor colour settings

13. Configure the editor to honour the working space and to warn on profile mismatch on open. Silent profile conversion is a common source of mystery colour drift. Set the editor to ask, not to silently convert.

14. Set the editor's policy for missing profiles to "ask when opening" rather than "assume sRGB". An untagged file may actually be in any space; assuming sRGB without asking propagates wrong colour silently.

15. Enable the editor's gamut warning sparingly. Gamut warnings are useful during soft proofing and noisy as a permanent overlay.

### Stage 5: Soft proofing for print

16. Obtain the destination ICC profile from the print lab. Most reputable labs publish their paper profiles freely. Do not rely on generic paper profiles — paper, ink, and printer interact and a generic profile may be a stop or more away from the actual output.

17. Enable soft proofing using the destination ICC profile, simulate the paper white, and simulate the ink black. Both simulations are important: without paper-white simulation the screen shows white brighter than the paper can deliver; without black-ink simulation the screen shows shadows deeper than the ink can achieve.

18. Pick the rendering intent. Two intents matter for photo work:

   - Perceptual: compresses the entire source gamut into the destination gamut, preserving relative relationships. Good for images with saturated colours that exceed the destination — landscapes, product reds, sunset skies.
   - Relative colorimetric with black-point compensation: maps in-gamut colours unchanged and clips out-of-gamut colours to the nearest in-gamut value, with black-point compensation pulling shadows up so they remain readable. Good for images dominated by in-gamut colour with a few out-of-gamut spikes — portraits and most editorial.

   Try both, view them side by side at the proofing display, and choose by image. Do not pick one once and apply to all images.

19. After soft proofing, make adjustments scoped to the print's needs without losing the screen-delivery version. Practical approach: keep the master file in the working space, save soft-proofed adjustments as an adjustment-layer group that is enabled only for the print export.

### Stage 6: Output

20. Convert to the destination colour space at export, do not assign. Convert preserves appearance across the gamut change; assign reinterprets the same numbers as if they meant something different and is almost always wrong here.

21. Pick the embedded profile by destination:

   - Web: sRGB embedded. Many web platforms strip profiles; sRGB is the safest fallback because most browsers and devices assume sRGB for untagged files.
   - iOS or macOS gallery for a wide-gamut audience: Display P3 embedded, with the understanding that some viewers see it as sRGB and will see slightly muted colour.
   - Print lab: the lab's paper-and-printer ICC profile if the lab requests pre-converted files, or Adobe RGB / ProPhoto if the lab does its own conversion. Ask the lab.
   - Archive: ProPhoto RGB at 16-bit TIFF, with the working master's profile embedded.

22. Apply output sharpening at export, sized to the destination resolution and to the medium. Screen, matte print, and glossy print absorb sharpening differently. A common starting calibration: less sharpening for glossy than matte, less for large prints than small, less for high-resolution screens than low. Verify with test prints once and document the chosen settings as a preset.

23. Verify the export. Open the exported file in a colour-managed viewer (not a system preview that may strip profiles). Compare against the editor's view. Differences here are colour-management failures, not editing failures, and need diagnosis before delivery.

### Stage 7: Audit and recovery

24. When colour disagreements appear between collaborators, audit in this order: the displays first (calibration date, target, room light); the working space and editor settings second; the file profiles third (open the file's profile in a colour utility and confirm it matches what was sent); the destination profiles last. Most disagreements resolve at the first level.

25. Maintain a profile inventory. List the camera profile in use per body, the display profile per workstation with calibration date, the working space in use per editor, and the destination profiles in use per output target. Without an inventory the troubleshooting at step 24 has nothing to compare against.

26. Replace profiles, do not edit them. Hand-edited ICC profiles are unsupportable. If a profile does not produce acceptable output, generate a new one from measurement, do not tweak the numbers.

## Reference pipeline templates

### Web-only delivery

- Camera profile: vendor matrix or standard.
- Working space: sRGB or Display P3 at 16-bit.
- Display calibration: D65, 120-160 cd/m², gamma 2.2, monthly.
- Editor policy: warn on profile mismatch.
- Soft proofing: not required.
- Output: sRGB embedded JPEG. Verify in browser before delivery.

### Mixed web and print delivery

- Camera profile: vendor standard or custom DCP for product work.
- Working space: Adobe RGB at 16-bit.
- Display calibration: D65, 100-120 cd/m², gamma 2.2, monthly.
- Editor policy: warn on profile mismatch; assume Adobe RGB for untagged files from this workflow only.
- Soft proofing: enabled for print exports against the lab paper profile, with paper-white and ink-black simulation.
- Output: sRGB JPEG for web; lab's paper profile or Adobe RGB TIFF for print depending on lab workflow.

### Fine-art print pipeline

- Camera profile: custom DCP from a reference target shot under the same light as production.
- Working space: ProPhoto RGB at 16-bit.
- Display calibration: D65 or D50 to match the print viewing booth; 80-100 cd/m²; weekly to bi-weekly.
- Editor policy: strict — warn on every profile event; never assume.
- Soft proofing: required on every frame against the lab's paper profile, both rendering intents tried.
- Output: convert to the lab's ICC profile, 16-bit TIFF, medium-specific output sharpening preset.

## Common failure modes

- **Screen and print disagree consistently in one hue**: a series of prints all read more magenta or more green than on screen. Caused by an out-of-date or wrong display profile, or by a paper profile that does not match the actual paper. Fix: recalibrate the display; confirm the paper profile matches the paper and printer combination being used.
- **Different displays in the same studio show the same file differently**: two editors disagree about a frame's colour. Caused by uncoordinated calibration targets (one workstation at D65, the other at native white point) or by different room lighting. Fix: standardise targets across workstations, write the standard into the profile inventory, and re-verify under matched ambient light.
- **Files look correct in the editor and wrong on the client's screen**: the destination colour space was wrong. Caused by exporting with the working profile embedded rather than the destination profile. Fix: convert to destination space at export; if the destination is uncertain, sRGB is the safe fallback.
- **Strip-on-upload destroys colour**: web platforms that strip profiles render embedded-AdobeRGB files as if they were sRGB. Caused by embedding a profile the destination cannot honour. Fix: convert to sRGB for any platform with profile-stripping behaviour.
- **Soft proof looks right, print does not**: ambient light during print viewing differs from ambient during soft proofing. Caused by viewing the print under a different light source. Fix: view prints under a D50 viewing booth or under standardised daylight where possible; soft-proof under matching white-point.
- **Gradient banding in the print**: smooth gradient on screen, visibly banded on paper. Caused by 8-bit working space or by aggressive curves on an 8-bit file. Fix: edit in 16-bit; verify gradient on screen at the print resolution before sending.

## Examples

Example invocation: "I shoot landscape on a wide-gamut camera, edit on a recent IPS display in a daylight-lit room, and print mostly through a fine-art lab on matte cotton rag. Plan my colour pipeline."

Expected output: ProPhoto RGB working space at 16-bit; D65 white point, 100 cd/m² luminance, gamma 2.2, recalibrate weekly because of the daylight room; lab paper profile downloaded and used for soft proofing with paper-white and black-ink simulation; perceptual rendering intent recommended for landscapes; export converts to the lab's ICC profile per their workflow doc; matte-specific output sharpening preset.

Second example: "Two-photographer studio, both delivering portrait work for the same client, complaints that the two sets don't match." Expected plan: standardise on Adobe RGB working space across both workstations; align display calibration targets (D65, 120 cd/m², gamma 2.2) with the same colorimeter on both displays in the same week; establish a shared reference frame and require both photographers to deliver the reference matched within tolerance before each shoot; record the calibration dates in a shared profile inventory.

Third example: "Web-only delivery for a fashion blog, photographer uses a wide-gamut display." Expected plan: Display P3 working space with the option to deliver as Display P3 if the audience analytics show wide-gamut device dominance, otherwise convert to sRGB at export; embed the destination profile on every export; verify a sample of exports in a non-colour-managed browser to confirm the colour holds.

## Limitations

This skill assumes ICC-based colour management. Some emerging wide-gamut workflows (HDR for screen, ACES for video, scene-referred linear pipelines) follow related but distinct principles; the skill notes the overlap but does not substitute for HDR-specific or motion-specific colour-management guidance. Calibration cadence and ambient-light recommendations are starting points — high-stakes commercial reproduction requires more rigorous measurement than a generic plan can specify. Print profiles are paper-and-ink-and-printer-specific; the only authoritative profile is the one the lab publishes, and a generic recommendation cannot substitute. The skill assumes a calibrated colorimeter or spectrophotometer is available; a workflow without one cannot be colour-managed beyond the system defaults.
