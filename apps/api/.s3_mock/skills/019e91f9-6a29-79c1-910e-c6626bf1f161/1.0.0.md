# Cloud Run Basics

## When to use

Use this skill when you need to deploy applications responding to HTTP requests (services), run event-triggered or scheduled tasks (jobs), or handle always-on pull-based background processing (worker pools).

## How to apply

Enable the Cloud Run and Cloud Build APIs, grant the required roles, then use `gcloud run deploy`, `gcloud run jobs create`, or `gcloud run worker-pools deploy` as appropriate. Ensure any deployed code listens on `0.0.0.0` and the injected `$PORT` environment variable. Use Artifact Registry for container images; fall back to source deployment with buildpacks when no Dockerfile is supplied.

## Overview

Cloud Run is a fully managed application platform for running your code, function, or container on top of Google's highly scalable infrastructure. It abstracts away infrastructure management, providing three primary resource types:

1. Services: respond to HTTP requests sent to a unique and stable endpoint, using stateless instances that autoscale.
2. Jobs: execute parallelizable tasks manually or on a schedule, run to completion.
3. Worker pools: handle always-on background workloads like Kafka consumers, Pub/Sub pull queues, or RabbitMQ consumers.

## Prerequisites

1. Enable the Cloud Run Admin and Cloud Build APIs:
   ```bash
   gcloud services enable run.googleapis.com cloudbuild.googleapis.com --quiet
   ```
2. If your project is under a domain-restriction org policy that restricts unauthenticated invocations, follow the "Testing private services" guidance.

### Required roles

- Cloud Run Admin (`roles/run.admin`) on the project
- Cloud Run Source Developer (`roles/run.sourceDeveloper`) on the project
- Service Account User (`roles/iam.serviceAccountUser`) on the service identity
- Logs Viewer (`roles/logging.viewer`) on the project

For Cloud Build, grant the Cloud Build service account the Cloud Run Builder (`roles/run.builder`) role.

## Deploy a Cloud Run service

> CRITICAL RULE: Any deployed code MUST listen on 0.0.0.0 (not 127.0.0.1) and use the injected `$PORT` environment variable (defaults to 8080), or it will crash on boot.

Deploy a container image:
```bash
gcloud run deploy SERVICE_NAME \
    --image IMAGE_URL \
    --region us-central1 \
    --allow-unauthenticated \
    --quiet
```

### Deploy from source

Default (with build):
```bash
gcloud run deploy SERVICE_NAME --source . --quiet
```

With automatic base image updates:
```bash
gcloud run deploy SERVICE_NAME --source . \
  --base-image BASE_IMAGE \
  --automatic-updates \
  --quiet
```

Without build (Preview):
```bash
gcloud beta run deploy SERVICE_NAME \
  --source APPLICATION_PATH \
  --no-build \
  --base-image=BASE_IMAGE \
  --command=COMMAND \
  --args=ARG \
  --quiet
```

## Create and execute a Cloud Run job

```bash
gcloud run jobs create JOB_NAME --image IMAGE_URL OPTIONS --quiet
gcloud run jobs execute JOB_NAME --quiet
gcloud run jobs execute JOB_NAME --wait --region=REGION --quiet
```

Useful options: `--tasks`, `--max-retries`, `--task-timeout`, `--parallelism`, `--execute-now`.

## Deploy a worker pool

```bash
gcloud run worker-pools deploy WORKER_POOL_NAME --image IMAGE_URL --quiet
# Or from source:
gcloud run worker-pools deploy WORKER_POOL_NAME --source . --quiet
```

## What to do if a deployment fails

1. IAM/Permission error: consult the IAM and Security reference.
2. Crash on boot / health-check failed: `gcloud logging read "resource.labels.service_name=SERVICE_NAME" --limit=20` for the exact runtime error.
3. Native dependency error (Node/Python): if using `--no-build`, switch to `--source .` (buildpacks) to compile native extensions properly for Linux.
