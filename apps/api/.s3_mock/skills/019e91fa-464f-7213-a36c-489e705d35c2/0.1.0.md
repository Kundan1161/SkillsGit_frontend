# Pharmacovigilance Signal Detection Planner

> **Mandatory disclaimer.** This skill produces methodology guidance for
> pharmacovigilance workflows. Outputs are not regulatory safety reports and
> have no role in real-time individual case safety reporting (which has
> statutory deadlines requiring qualified PV staff). Use only as a
> planning/training aid; every real PV decision must be authorized by a
> qualified PV professional and signed off by the EU-QPPV or equivalent.

## When to use

Invoke this skill when a pharmacovigilance team, a clinical safety scientist,
or a student of drug safety asks you to:

- design (or refresh) a recurring disproportionality-analysis sweep against a
  spontaneous-reporting database (FAERS, VigiBase, VAERS, EudraVigilance, or a
  national equivalent);
- decide which statistics to use (PRR, ROR, EBGM/MGPS, BCPNN-IC) and at what
  thresholds;
- plan robustness analyses (stratification, subgroup, time-slice, masking
  correction, drug interaction);
- outline the triage steps that turn a numeric signal into a documented
  signal-evaluation activity.

Do **not** invoke this skill to:

- produce an actual ICSR (individual case safety report);
- file an expedited 15-day report;
- replace the company core data sheet, reference safety information, or
  signal-management SOP;
- generate any output that would be submitted to a regulator as-is.

## How to apply

Work through the eight phases below in order. Each phase produces a labeled
section in the final markdown deliverable. If the user has not supplied an
input the phase requires, ask one focused clarifying question, then proceed
with explicit assumptions.

### Phase 1 — Frame the scope

1. Restate the product / class / therapeutic area in one sentence.
2. State the database(s) chosen and why (FAERS for US post-market;
   EudraVigilance for EEA; VigiBase for global; VAERS for US vaccines; a
   company safety database for company-held data).
3. Define the time window: cumulative since first authorization, rolling
   12 months, or aligned to the data-lock-point of the next periodic report.
4. List the *exposure proxy* in use (e.g. number of reports as denominator,
   distributed doses, patient-years where available). Note that spontaneous
   reporting denominators are weak — never imply absolute incidence.
5. State the MedDRA version and level(s) for analysis (Preferred Term plus
   one Standardised MedDRA Query group where applicable).

### Phase 2 — Choose the disproportionality statistics

Recommend a primary statistic and at least one corroborating statistic.

| Statistic | Strength | Weakness | Typical primary use |
|---|---|---|---|
| PRR (Proportional Reporting Ratio) | Simple, transparent, easy to defend | Unstable at low cell counts; sensitive to masking | First-pass screening on large databases |
| ROR (Reporting Odds Ratio) | Closer to a true odds ratio; works with logistic regression | Same low-count instability | Confirmatory after PRR; supports subgroup logistic models |
| EBGM (Empirical Bayes Geometric Mean / MGPS) | Shrinkage to the null stabilises low cell counts | Black-box feel for some reviewers; needs prior choice | Large databases (FAERS, VigiBase) where rare events dominate |
| IC (BCPNN Information Component) | Bayesian, explicit uncertainty interval | Conceptually less familiar to clinicians | VigiBase-style routine screening |

Default recommendation when uncertain: **PRR as primary screen, EBGM as
shrinkage-corrected confirmation, IC as Bayesian cross-check** if the database
supports it.

### Phase 3 — Set thresholds

Map the user's `thresholds_preference` to a quantitative rule. These are
*defaults to start a discussion*, not regulatory limits:

- Conservative (high specificity, fewer false positives):
  - PRR ≥ 3 **and** chi-square ≥ 4 **and** ≥ 5 cases.
  - EBGM05 (lower 5% CI) ≥ 2.
  - IC025 (lower 2.5% CI) > 0.
- Balanced (default):
  - PRR ≥ 2 **and** chi-square ≥ 4 **and** ≥ 3 cases.
  - EBGM05 ≥ 1.
  - IC025 > 0.
- Sensitive (early-warning, high false-positive rate accepted):
  - PRR ≥ 2 **and** ≥ 3 cases (drop chi-square).
  - EBGM ≥ 1.

State explicitly: "These thresholds do not represent causation; they flag
combinations for human review."

### Phase 4 — Plan robustness analyses

For every flagged combination, plan at least three of:

1. **Stratification** by age band (paediatric / adult / elderly), sex, and
   reporter type (consumer vs. healthcare professional).
2. **Time-slice analysis** — split the window into pre- and post-label-change
   periods, or quarter-by-quarter, to detect notoriety / Weber-effect bias.
3. **Drug-class masking check** — re-run the statistic after removing the
   index drug from the comparator group ("excluded" PRR/ROR), since a
   high-prevalence drug within its own class can mask a true class effect.
4. **Concomitant-medication adjustment** — flag whether a known cause
   (e.g. anticoagulant in a bleeding signal) is co-reported in ≥ 30 % of
   cases.
5. **MedDRA-level robustness** — repeat at PT, HLT and SMQ to check the
   signal is not an artefact of one preferred term.
6. **Indication-stratified analysis** — when the same molecule has multiple
   indications with very different risk profiles.

### Phase 5 — Define the triage workflow

Produce a numbered triage path that the safety scientist will follow when a
combination crosses threshold:

1. **Deduplicate** at case level (latest-version-only) per FDA / EMA
   recommendations; document the deduplication rule (e.g. case-version
   selection by latest receipt date).
2. **Medical review** of the underlying case narratives for the top *k*
   cases (typical k = 20 or all if fewer).
3. **Confounding screen** — indication confounding, protopathic bias,
   channeling.
4. **Literature scan** — PubMed + EMA / FDA labels + the WHO UMC global
   signal list, time-boxed (e.g. 2 hours).
5. **Comparison to reference safety information** — is the event already
   listed? In what frequency category?
6. **Disposition recommendation**: closed (known/labelled), watching-brief
   (insufficient evidence), validated signal (to be escalated to signal
   evaluation), or refuted.

### Phase 6 — Documentation expectations

Specify the artefacts the analyst must produce so the work is auditable:

- Analysis plan (frozen before the run).
- Code or query log, including software version.
- Output tables (drug × event × statistic × CI).
- Validated-signal log entry, with date, owner, and next review date.
- Linkage to the signal-management SOP and EU-QPPV oversight log.

### Phase 7 — Follow-up actions and escalation

For each validated signal, propose a default escalation:

- Routine label-change pathway (variation under the relevant procedure).
- Direct healthcare professional communication (DHPC) if benefit-risk
  appears to shift.
- Risk-management-plan update (new important identified / potential risk).
- Inclusion in the next PBRER / PSUR signal section (see the
  *Periodic Safety Report Architect* skill).
- Targeted observational study or registry analysis if signal needs
  external corroboration.

### Phase 8 — Known limitations to disclose in the plan

Always close the plan with an honest limitations section. Cover at minimum:

- Spontaneous reports are not denominator-controlled; rates cannot be
  computed from them.
- Reporting bias varies by country, channel, and media attention.
- MedDRA hierarchy choices materially affect detection.
- Disproportionality is *association*, not causation.
- Re-analysis with different deduplication or different reference set will
  change the numbers; this is expected.

## Inputs

- `product_or_scope` — drug, class, vaccine, area, plus chosen database.
- `time_window` — reporting window.
- `known_risks` — optional, to triage already-labelled events.
- `thresholds_preference` — conservative / balanced / sensitive.

## Outputs

A single markdown document with the eight phase sections above, ready for the
qualified PV professional to review, edit, and sign off before any use in a
regulated process.

## Worked example (vaccine signal sweep)

A pharmacovigilance team supports a recently authorised adult vaccine and
wants a quarterly VAERS sweep aligned with the PBRER cadence. A balanced
plan produced by this skill would look like:

- **Phase 1.** Scope: vaccine X, US VAERS plus literature scan; rolling
  90-day window plus cumulative-since-launch view; denominator =
  distributed doses (best available proxy, acknowledged weakness); MedDRA
  v27.1 at PT and SMQ levels (Anaphylactic reaction SMQ, Demyelination
  SMQ).
- **Phase 2.** PRR primary, EBGM confirmatory. IC dropped because VAERS
  cell counts are stable enough for shrinkage but the team does not have a
  BCPNN-validated pipeline.
- **Phase 3.** Balanced thresholds: PRR ≥ 2 with chi-square ≥ 4 and ≥ 3
  cases; EBGM05 ≥ 1.
- **Phase 4.** Robustness: stratify by age band (18–49, 50–64, 65+) and
  by reporter type (HCP vs consumer); time-slice by quarter; check for
  notoriety bias if media coverage spiked; SMQ-level robustness for
  Anaphylactic reaction.
- **Phase 5.** Triage: deduplicate at VAERS_ID level keeping the latest
  version; medical review of top 20 anaphylaxis cases; literature scan;
  comparison to the package insert.
- **Phase 6.** Outputs: frozen analysis plan; SQL or R query log;
  drug×event table; signal log entry per validated signal.
- **Phase 7.** Validated-signal actions: feed into the next PBRER
  signals section; trigger an RMP review meeting; consider a self-
  controlled case-series study with the CDC dataset if signal persists.
- **Phase 8.** Limitations stated up front.

## Edge cases the planner must call out

1. **Newly authorised product (< 12 months on market).** Disproportionality
   is unstable; recommend descriptive case-series review alongside, and
   widen confidence intervals interpretation.
2. **Combination product.** Plan analyses for each component and for the
   combination; mask each from the comparator set in turn.
3. **Class effect under investigation.** Pre-specify whether the comparator
   is "all other drugs" or "all other drugs in the class"; both should be
   reported.
4. **Concomitant indication with high background event rate** (e.g. anti-
   cancer agents with cytopenias). State the indication-stratified PRR and
   note confounding by indication explicitly.
5. **Vaccine-specific issues.** Background rates of intercurrent illness
   matter; pre-specify use of observed-vs-expected for at least one event
   if a public-health background rate is available.
6. **Reporting-rate inflation events.** Regulatory letters, media stories,
   and litigation can spike reports; the time-slice analysis should
   visualise this and the analyst should not treat the spike alone as a
   signal.
7. **Small populations.** For paediatric or rare-disease products, drop
   thresholds to "sensitive" and emphasise case-by-case clinical review.

## Cadence and governance

State explicitly in the deliverable:

- The sweep runs **quarterly** by default, aligned to the data-lock-point
  of the next periodic report; some products warrant monthly cadence
  during the first year post-launch.
- The signal-management committee reviews validated signals before they
  enter the periodic report.
- The EU-QPPV (or equivalent in the relevant region) signs off the signal
  decisions; the analyst does not.
- Audit trail: every threshold change, every deduplication rule change,
  and every comparator-set change is versioned.

## Limitations

This skill **does not**:

- query any safety database;
- compute any disproportionality statistic;
- substitute for a documented signal-management SOP;
- determine causality;
- decide on label changes or DHPC issuance.

It produces a *plan* that a qualified pharmacovigilance professional must
adapt, approve, and sign off — with the EU-QPPV or equivalent retaining
ultimate responsibility.

## Quality checks before the plan is approved

Before circulating the plan to the signal-management committee, verify:

- The scope sentence names the product, database, and window in one line.
- The choice of primary and corroborating statistic is justified against
  the database type and event prevalence.
- Thresholds are stated as numbers, not adjectives.
- At least three robustness analyses are pre-specified.
- The triage workflow names an owner for each step.
- The limitations section is included and not softened.
- The cadence sentence is unambiguous.

## How this skill differs from a signal-management SOP

A signal-management SOP is a controlled, versioned, regulator-facing
document that the company must follow. This skill outputs a *plan for one
analysis run* that fits **inside** an existing SOP. The skill never:

- redefines the company SOP;
- changes the signal-management committee structure;
- alters QPPV oversight;
- documents itself as a procedure.

If the user appears to have no SOP at all, the assistant must say so and
recommend that an SOP be authored — separately, by qualified PV staff —
before any plan is operationalised.
