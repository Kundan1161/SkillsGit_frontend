# Expo UI Guidelines

## When to use

Use this skill when building Expo apps with Expo Router — choosing libraries, structuring routes, styling components, configuring navigation, and adding animations following Apple Human Interface Guidelines.

## How to apply

Always try Expo Go before creating custom builds. Use the conventions, library preferences, and styling rules below to produce idiomatic, on-platform UIs. Account for safe areas everywhere.

## Running the App

**CRITICAL: Always try Expo Go first before creating custom builds.**

Most Expo apps work in Expo Go without any custom native code. Before running `npx expo run:ios` or `npx expo run:android`:

1. **Start with Expo Go**: `npx expo start` and scan the QR code.
2. **Check if features work** thoroughly in Expo Go.
3. **Only create custom builds when required**.

### When Custom Builds Are Required

You need `npx expo run:ios/android` or `eas build` ONLY when using:

- **Local Expo modules** (custom native code in `modules/`)
- **Apple targets** (widgets, app clips, extensions via `@bacons/apple-targets`)
- **Third-party native modules** not included in Expo Go
- **Custom native configuration** that can't be expressed in `app.json`

## Code Style

- Be cautious of unterminated strings; escape nested backticks and quotes.
- Always use import statements at the top of the file.
- Always use kebab-case for file names, e.g. `comment-card.tsx`.
- Remove old route files when restructuring navigation.
- No special characters in file names.
- Configure tsconfig.json with path aliases, prefer aliases over relative imports.

## Routes

- Routes belong in the `app` directory.
- "Never co-locate components, types, or utilities in the app directory. This is an anti-pattern."
- Ensure the app always has a route matching "/".

## Library Preferences

- Never use modules removed from React Native (Picker, WebView, SafeAreaView, AsyncStorage).
- Never use legacy `expo-permissions`.
- `expo-audio` not `expo-av`. `expo-video` not `expo-av`.
- Use `expo-image` with `source={{ uri: "sf:name" }}` for SF Symbols.
- `react-native-safe-area-context` not RN's `SafeAreaView`.
- `process.env.EXPO_OS` not `Platform.OS`.
- `React.use` not `React.useContext`.
- `expo-image` `Image` instead of intrinsic `img`.
- `expo-glass-effect` for liquid glass backdrops.

## Responsiveness

- Always wrap root component in a scroll view for responsiveness.
- Use `<ScrollView contentInsetAdjustmentBehavior="automatic" />` instead of `<SafeAreaView>`.
- Apply `contentInsetAdjustmentBehavior="automatic"` to FlatList and SectionList too.
- Use flexbox instead of Dimensions API.
- Prefer `useWindowDimensions` over `Dimensions.get()`.

## Behavior

- Use `expo-haptics` conditionally on iOS for delightful experiences.
- Use views with built-in haptics like `<Switch />` and `@react-native-community/datetimepicker`.
- A Stack route's first child should almost always be a ScrollView.
- Prefer `headerSearchBarOptions` in Stack.Screen options to add a search bar.
- Use the `<Text selectable />` prop on copyable data.
- Format large numbers like 1.4M, 38k.

## Styling — General

Follow Apple Human Interface Guidelines.

- Prefer flex gap over margin/padding.
- Prefer padding over margin where possible.
- Always account for safe area (stack headers, tabs, or `contentInsetAdjustmentBehavior="automatic"`).
- Inline styles, not `StyleSheet.create`, unless reusing.
- Add entering/exiting animations for state changes.
- `{ borderCurve: 'continuous' }` for rounded corners unless creating a capsule.
- Use a navigation stack title instead of a custom text element.
- When padding a ScrollView, use `contentContainerStyle` instead of padding on the ScrollView.
- CSS and Tailwind not supported in core RN — use inline styles (or NativeWind, see separate skill).

## Text

- Add the `selectable` prop to every `<Text/>` displaying important data or errors.
- Counters use `{ fontVariant: 'tabular-nums' }` for alignment.

## Shadows

```tsx
<View style={{ boxShadow: "0 1px 2px rgba(0, 0, 0, 0.05)" }} />
```

Use CSS `boxShadow` style prop. Never use legacy RN shadow or elevation styles. `inset` shadows are supported.

## Navigation — Link

```tsx
import { Link } from 'expo-router';

<Link href="/path" />

<Link href="/path" asChild>
  <Pressable>...</Pressable>
</Link>
```

Whenever possible, include a `<Link.Preview>` to follow iOS conventions. Add context menus and previews frequently.

## Stack

- Always use `_layout.tsx` files to define stacks.
- Use `Stack` from `expo-router/stack` for native navigation stacks.
- Set page title in `Stack.Screen options={{ title: "Home" }}`.

## Context Menus + Link Preview

```tsx
<Link href="/settings" asChild>
  <Link.Trigger>
    <Pressable><Card /></Pressable>
  </Link.Trigger>
  <Link.Menu>
    <Link.MenuAction title="Share" icon="square.and.arrow.up" onPress={handleShare} />
    <Link.MenuAction title="Block" icon="nosign" destructive onPress={handleBlock} />
  </Link.Menu>
</Link>
```

## Modal & Sheet

```tsx
<Stack.Screen name="modal" options={{ presentation: "modal" }} />

<Stack.Screen
  name="sheet"
  options={{
    presentation: "formSheet",
    sheetGrabberVisible: true,
    sheetAllowedDetents: [0.5, 1.0],
    contentStyle: { backgroundColor: "transparent" },
  }}
/>
```

`contentStyle: { backgroundColor: "transparent" }` makes the background liquid glass on iOS 26+.

## Common Route Structure

```
app/
  _layout.tsx — <NativeTabs />
  (index,search)/
    _layout.tsx — <Stack />
    index.tsx — Main list
    search.tsx — Search view
```

```tsx
// app/_layout.tsx
import { NativeTabs, Icon, Label } from "expo-router/unstable-native-tabs";

export default function Layout() {
  return (
    <NativeTabs>
      <NativeTabs.Trigger name="(index)">
        <Icon sf="list.dash" />
        <Label>Items</Label>
      </NativeTabs.Trigger>
      <NativeTabs.Trigger name="(search)" role="search" />
    </NativeTabs>
  );
}
```
