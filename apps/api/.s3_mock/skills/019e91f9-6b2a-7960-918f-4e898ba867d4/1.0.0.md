# Cloud Firestore — Database and Operations

## When to use

Use this skill when setting up, managing, or executing queries against Cloud Firestore database instances — covering both Standard and Enterprise (native mode) editions.

## How to apply

Always identify which Firestore edition you're targeting first. Existing databases may be STANDARD or ENTERPRISE/native — checks differ. For new projects, prefer Enterprise edition unless legacy compatibility is required. Then follow the appropriate provisioning, security rules, data modeling, SDK usage, and indexing reference for the edition.

## First Step — Identify the Instance

1. Does the user have an existing Firestore database, or do they need to create one?
2. If existing, list available databases and check each instance's edition.

## Workflow Branches

- **Inspect existing** — Check edition (STANDARD vs ENTERPRISE/native), follow the matching reference.
- **Create new** — Default to Enterprise edition. Pick an appropriate location from available regions.

## Reference Topics Covered

- Provisioning (CLI flags, region selection)
- Security rules (`request.auth`, ownership, role checks)
- Data modeling (collections, subcollections, denormalization tradeoffs)
- SDK usage (Web, Mobile, Server Admin)
- Indexes (composite, single-field, exemptions)
