# Expo Router API Routes

## When to Use API Routes

Use API routes when you need:

- **Server-side secrets** — API keys, database credentials, tokens that must never reach the client.
- **Database operations** — Direct database queries that shouldn't be exposed.
- **Third-party API proxies** — Hide API keys when calling OpenAI, Stripe, etc.
- **Server-side validation** — Validate before database writes.
- **Webhook endpoints** — Receive callbacks from Stripe, GitHub, etc.
- **Rate limiting** at the server level.
- **Heavy computation** offloaded from mobile.

## When NOT to Use API Routes

- Data is already public — use direct fetch.
- No secrets required — static or client-safe operations.
- Real-time updates — use WebSockets or services like Supabase Realtime.
- Simple CRUD — consider Firebase, Supabase, Convex.
- File uploads — use direct-to-storage (S3 presigned URLs, R2).
- Authentication only — use Clerk, Auth0, Firebase Auth.

## How to apply

Place API routes in the `app` directory with a `+api.ts` suffix. Export named functions per HTTP method. Read environment variables via `process.env`. Deploy with `eas deploy`. Routes run on Cloudflare Workers, so prefer Web APIs and cloud databases.

## File Structure

```
app/
  api/
    hello+api.ts          → GET /api/hello
    users+api.ts          → /api/users
    users/[id]+api.ts     → /api/users/:id
  (tabs)/
    index.tsx
```

## Basic API Route

```ts
// app/api/hello+api.ts
export function GET(request: Request) {
  return Response.json({ message: "Hello from Expo!" });
}
```

## HTTP Methods

```ts
// app/api/items+api.ts
export function GET(request: Request) {
  return Response.json({ items: [] });
}

export async function POST(request: Request) {
  const body = await request.json();
  return Response.json({ created: body }, { status: 201 });
}

export async function PUT(request: Request) {
  const body = await request.json();
  return Response.json({ updated: body });
}

export async function DELETE(request: Request) {
  return new Response(null, { status: 204 });
}
```

## Dynamic Routes

```ts
// app/api/users/[id]+api.ts
export function GET(request: Request, { id }: { id: string }) {
  return Response.json({ userId: id });
}
```

## Query Parameters

```ts
export function GET(request: Request) {
  const url = new URL(request.url);
  const page = url.searchParams.get("page") ?? "1";
  return Response.json({ page });
}
```

## Headers / Auth

```ts
export function GET(request: Request) {
  const auth = request.headers.get("Authorization");
  if (!auth) return Response.json({ error: "Unauthorized" }, { status: 401 });
  return Response.json({ authenticated: true });
}
```

## Environment Variables

Use `process.env` for server-side secrets:

```ts
const response = await fetch("https://api.openai.com/v1/chat/completions", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.OPENAI_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ model: "gpt-4", messages: [{ role: "user", content: prompt }] }),
});
```

Set via `.env` locally, or `eas env:create` for EAS Hosting.

## CORS

```ts
const corsHeaders = {
  "Access-Control-Allow-Origin": "*",
  "Access-Control-Allow-Methods": "GET, POST, PUT, DELETE, OPTIONS",
  "Access-Control-Allow-Headers": "Content-Type, Authorization",
};

export function OPTIONS() {
  return new Response(null, { headers: corsHeaders });
}
```

## Cloudflare Workers Runtime Constraints

- **No Node.js filesystem** — `fs` unavailable.
- **No native Node modules** — use Web APIs or polyfills.
- **30s timeout** for CPU-intensive tasks.
- **No persistent connections** — WebSockets need Durable Objects.
- **Use Web Crypto** instead of `node:crypto`.

### Database Options

Use cloud databases: Cloudflare D1, Turso, PlanetScale, Supabase, Neon.

```ts
import { createClient } from "@libsql/client/web";

const db = createClient({
  url: process.env.TURSO_URL!,
  authToken: process.env.TURSO_AUTH_TOKEN!,
});

export async function GET() {
  const result = await db.execute("SELECT * FROM users");
  return Response.json(result.rows);
}
```

## Auth Middleware Pattern

```ts
// utils/auth.ts
export async function requireAuth(request: Request) {
  const token = request.headers.get("Authorization")?.replace("Bearer ", "");
  if (!token) {
    throw new Response(JSON.stringify({ error: "Unauthorized" }), {
      status: 401,
      headers: { "Content-Type": "application/json" },
    });
  }
  return { userId: "123" };
}
```

## Rules

- NEVER expose API keys or secrets in client code.
- ALWAYS validate and sanitize user input.
- Use proper HTTP status codes (200, 201, 400, 401, 404, 500).
- Handle errors gracefully with try/catch.
- One responsibility per endpoint.
- Use TypeScript for type safety.
- Log errors server-side for debugging.
