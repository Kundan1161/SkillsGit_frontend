# Find Bugs — Branch Review Methodology

## When to use

Use this skill when reviewing code changes on a Git branch to identify bugs, security vulnerabilities, and quality issues prior to merge.

## How to apply

Walk the five phases below in order. Avoid false positives by verifying each potential issue is real and unaddressed before reporting. Prioritize findings as: security > bugs > code quality. Exclude purely stylistic issues.

## Phase 1 — Retrieve the Diff

Get the complete diff between the default branch and current HEAD. If the output is truncated, read individual files to ensure comprehensive coverage.

## Phase 2 — Map the Attack Surface

Catalog:

- User inputs (HTTP params, form fields, file uploads).
- Database operations.
- Authentication checks.
- State management.
- External integrations.
- Cryptographic functions.

## Phase 3 — Apply the Security Checklist

- Injection attacks (SQL, NoSQL, command, LDAP, template).
- XSS vulnerabilities.
- Authentication enforcement.
- Authorization controls.
- CSRF protection.
- Race conditions.
- Session security.
- Cryptographic practices (weak randomness, hardcoded keys, bad modes).
- Information disclosure risks.
- Denial-of-service vectors.
- Business logic flaws.

## Phase 4 — Verify Each Finding

For every potential issue:

- Confirm it hasn't already been addressed elsewhere in the diff.
- Check for existing test coverage that would catch it.
- Examine surrounding context (call sites, types, runtime guards).

## Phase 5 — Report

Document:

- All reviewed files.
- Checklist status for each item.
- Verification limitations (what you could not assess).
- Final conclusions.

## Finding Format

For each issue:

- **File:Line**
- **Severity** — Critical / High / Medium / Low
- **Problem description**
- **Supporting evidence** (snippet, control flow)
- **Concrete remediation**
- **Relevant standard** (CWE/OWASP/internal rule)

## Reporting Standards

Findings are prioritized as **security vulnerabilities > bugs > code quality**, excluding stylistic issues. The methodology emphasizes avoiding false positives by confirming issues are genuine and unaddressed before reporting.
