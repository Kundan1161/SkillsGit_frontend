# GitHub Actions Security Review

## When to use

Use this skill when conducting a security review of GitHub Actions workflows — focusing on exploitable vulnerabilities with concrete attack scenarios.

## How to apply

Classify triggers first, load relevant attack references, validate findings by tracing complete attack paths, and report only HIGH or MEDIUM confidence findings with all five required elements. Apply safe patterns to avoid false positives on `${{ }}` inside `if:` / `with:`, numeric expressions, or anything requiring write access.

## Workflow

1. **Classify triggers** in workflows and load relevant attack references.
2. **Check vulnerability classes**:
   - Pwn requests
   - Expression injection
   - Unauthorized commands
   - Credential escalation
   - Config poisoning
   - Supply chain (third-party actions, untrusted refs)
   - Permissions / secrets misconfiguration
   - Runner infrastructure risks
3. **Validate findings** by tracing complete attack paths — no theoretical issues.
4. **Report only HIGH/MEDIUM confidence** findings with all five elements.
5. **Apply safe patterns** — don't flag `${{ }}` in `if:`/`with:`, numeric expressions, or patterns requiring write access.

## Threat Model

External attackers (no write access) exploiting:

- Fork PRs
- Issues
- Comments
- Branch names

## Required Finding Elements

For each finding:

1. **Entry point** — trigger and field where attacker controls input.
2. **Payload** — concrete attack string.
3. **Execution mechanism** — how the payload is reached.
4. **Impact** — what the attacker gains (secrets, code execution, repo write).
5. **PoC sketch** — minimal reproduction.

## Output Format

- Raw file contents when requested.
- Findings with exploitation scenarios + fixes.
- Zero findings if no vulnerabilities confirmed — do not invent.
- Max 125 characters for source quotes.

## False-Positive Patterns (Skip)

- `${{ ... }}` only used inside `if:` or `with:` value of trusted actions.
- Numeric expressions.
- Issues requiring repo write access by the attacker.
- Hardcoded scripts not parameterized by untrusted input.
